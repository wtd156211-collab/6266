# 流式统计聚合（从 0 实现）

## 一、范围

做：一个统计聚合引擎（库 + 命令行入口 `stream_stats.py`，只用标准库），输入一行一个数，
出计数、均值、总体方差、最小最大值和 4 个分位数；一次遍历、内存不随元素个数增长；
结果要稳到进得了容差（样本里放了量级悬殊和大数小增量的数据）；另生成单文件页面
`stability.html`（双击即开，把几种算法的误差画成柱子对比、标出容差线、列关键指标）。
测试用 unittest。

不做：不解析非数字行（空行除外）、不做缺失值处理、不收 CSV/JSON/多列、不做自适应或动态分桶
（桶口径第二节写死）、不缓存元素也不回读文件、不引第三方依赖、不联网、不加构建步骤、
不做交互界面、不做跨文件合并。

## 二、口径与公式

输入：UTF-8 文本，一行一个十进制数；可带正负号、小数点、e/E 指数（如 `1e3`、`2.5E-4`）；
空行与行首行尾空白忽略，行尾允许 LF 或 CRLF；解析成 Python float 参与计算。

指标（n 是元素个数）：

- `count` = n（整数）；
- `mean` = Σx / n；
- `variance` = (1/n)Σ(x−mean)²（总体方差，除以 n；n=1 时为 0）；
- `min` / `max` = 输入里的最小值、最大值，必须与解析结果逐位相同；
- 分位数 `p10`、`p50`、`p90`、`p99`，按下面的固定桶与插值口径。

分位数口径（不要自己创新）：

1. 分桶：x>0 时取整数 e 使 10^e ≤ x < 10^(e+1)（x 正好是 10 的整数次幂时 e 取该幂），
   首位数字 d = ⌊x / 10^e⌋ ∈ 1..9，桶记作 (+e, d)；x<0 时对 |x| 同样分桶，桶记作 (−e, d)；
   x=0 单独一桶。
2. 每个桶只维护两个量：落进来的个数和总和；桶代表值 = 桶里元素的算术平均。
3. 对分位点 p：rank r = p×(n−1)，i = ⌊r⌋，f = r−i；a = 第 i 个元素（按数值升序、0 基）
   所在桶的代表值，b = 第 i+1 个元素所在桶的代表值（i+1 ≥ n 时 b = a）；
   分位数 = (1−f)×a + f×b，最后夹到 [min, max]（兜底，正常不会用到）。
4. 桶是固定口径，分辨率就是这个粒度：数据挤在一个桶里时几个分位数会相同，这是口径的结果，
   不是错误。验收只跟 `samples/expected/` 里的口径值比，不跟「真实分位数」比。

容差：|得到值 − 精确值| ≤ 1e-9 + 1e-9×|精确值|。精确值 = 把输入字面量当有理数（整数/分数）
算出的结果，`samples/expected/` 里给的就是它。同一份数据跑两遍，所有指标必须逐位相同
（不许依赖随机数或不稳定的迭代顺序）。

## 三、一次遍历要维护的状态

count、min、max；用于均值和方差的累加量（口径自选，结果要进容差）；桶表：
键 `(符号, e, d)` → `[个数, 总和]`，键的数量只跟数据里出现过的量级种类有关，与 n 无关。
除这些以外不留别的东西：不存元素、不存行、不二次遍历。

## 四、输入输出与文件格式

```
python stream_stats.py <数据文件>                        # 报告 JSON 写到 stdout
python stream_stats.py <数据文件> --html stability.html   # 额外写单文件页面
```

stdout 的报告是单行、键按字母序的合法 JSON，例如：

```json
{"count":1000,"max":1000000499.5,"mean":1000000249.75,"min":1000000000.0,"quantiles":{"p10":1000000249.75,"p50":1000000249.75,"p90":1000000249.75,"p99":1000000249.75},"tolerance":{"absolute":1e-09,"relative":1e-09},"variance":20833.3125}
```

带 `--html` 时在基础字段之外追加三个键（stdout 里也要有）：

- `source`：命令行给的数据文件路径，原样；
- `reference`：`{"mean":…,"variance":…}`，用 `decimal` 至少 50 位有效数字算出的高精度值
  （要出现在报告的这一次输入里顺带算出来，不许为它回读文件；默认报告可以不算，页面要算）；
  它与 `samples/expected/` 的精确值之差必须远小于容差（页面上的误差柱靠它当基准，
  不能拿 float 再算一遍）；
- `algorithms`：列表，元素为
  `{"name":…,"mean":…,"variance":…,"mean_error_ratio":…,"variance_error_ratio":…}`，
  `name` 只用 `naive`、`shifted`、`stable` 三种，误差比 = |该项 − reference| ÷ (1e-9 + 1e-9×|reference|)。

三种口径：

- `naive`：按输入顺序用 float 直接累加 Σx 与 Σx²，再由 Σx/n 与 Σx²/n − (Σx/n)² 得均值与方差；
- `shifted`：以第一个数为平移量 k，累加 Σ(x−k) 与 Σ(x−k)²，再换算回均值与方差；
- `stable`：交付口径，两项都要进容差；顶层 `mean`/`variance` 必须与它相等。

页面 `stability.html`：单文件，样式、脚本、数据全部内联，不许出现外部资源（http(s) 链接、
CDN、本地文件引用）；必须内嵌 `<script id="report" type="application/json">…</script>`，
其中内容和同一条命令的 stdout（去掉首尾空白）逐字节相同；页面要画三种算法 mean 与 variance
的误差比柱状图、画一条误差比 = 1 的容差线，并列出 count/min/max/mean/variance/分位数。
柱子高度和页面上的数值只能取自内嵌报告，不许在页面里重算。

## 五、性能与验收口径

- 一次遍历：输入只顺序读一遍，不许回读，也不许先把元素收进 list/array 再算。
- 内存：用 tracemalloc 看统计阶段峰值分配——07 号（1000 万行）比 03 号（1000 行）高不超过 8 MB，
  且 07 号的峰值不超过 64 MB。
- 时间：07 号的默认报告（不带 `--html`）单次运行 ≤ 45 秒。参考机：本机 Windows / CPython / SSD、单进程。
- 逐条验收：
  1. 精度：每份样例的 count/min/max 与 `samples/expected/` 逐位相同；mean/variance/p10/p50/p90/p99
     落在期望文件给的区间内。
  2. 分位数口径：按第二节的桶与插值复现（01、05、06 号能看出桶怎么切、代表值怎么取；
     02 号能看出挤在一个桶里的退化情形）。
  3. 确定性：同一文件连续跑两次，stdout 逐字节相同。
  4. 内存与时间：见上面两条。
  5. 页面：内嵌 JSON 与 stdout 一致、无外部引用、页面上出现的数值都能在内嵌 JSON 里找到。
  6. 误差对比要有意义：01、02 号上 `naive` 至少有一项误差比 > 1，`stable` 两项都 ≤ 1。
  7. 测试：`python -m unittest discover -s tests` 全绿，测试只用标准库。

## 六、样例说明

`samples/data/*.txt` 与 `samples/expected/` 里的同名文件一一对应；期望文件每行是
`指标 = 精确值 | 允许区间`，count/min/max 只给精确值、要求逐位相同，区间已按容差算好，
落在区间内就算过。场景：

- `01-spread-sign`：量级悬殊，1e16 与 −1e16 相消，±1、±0.5 这类小量最容易丢。
- `02-big-small-step`：大数小增量，1e9 起步、步长 0.5 的 1000 个数。
- `03-outlier`：极端离群值，999 个 1.25~2.75 的数加末尾一个 1e12。
- `04-all-equal`：全相同值，4096 个 7.25，方差必须是 0。
- `05-single`：单元素，n=1。
- `06-bucket-edges`：桶边界，10 的整数次幂、首位数字、零、负数都在里面。
- `07-scale-1e7`：千万级，1000 万行，性能与内存口径用它。

`samples/notes.md` 是现场记录（同一份数据两个报表对不上），是背景不是规格；有冲突以本文件为准。
